# Testing strategy

Last updated: 2026-11-16. Status: in place. CI (`.github/workflows/ci.yml`) runs three jobs on every PR and push to `main`: **Web** (lint, format check, types, Vitest, build, Playwright), **API** (Ruff, mypy, migrations, pytest with `--integration` against service containers) and **Secret scan** (gitleaks).

## Layers

| Layer | Tool | Scope | Runs in |
|---|---|---|---|
| API unit | pytest (`apps/api/tests`), Hypothesis for the engine | Services, the eligibility engine, provider adapters (recorded responses through `httpx.MockTransport`, no network), schema validation, rate and body limits, MCP tools | `pnpm test:api` locally, CI on every PR |
| API integration | pytest `@pytest.mark.integration` + real Postgres+PostGIS and Redis | Seeding, endpoints through `httpx.AsyncClient`, geo queries, the Postgres fare ledger under concurrency, MCP answers vs the API | Skipped unless `pytest --integration` (`pnpm test:api:integration` against `docker compose`); CI uses service containers `postgis/postgis:17-3.7` and `redis:7.4` |
| Migrations | `test_migrations.py`: Alembic upgrade → downgrade → upgrade | Every migration is reversible | CI (integration) |
| Seed validation | The seed loader's checks (`python -m app.seed --check`) | Every record has provenance. References resolve. No `verified` record without a primary source, date and checker. Unchecked imported cards never answer a plain "yes" | `test_seed.py` on the repository files in every pytest run (fails the build); `deploy-data.yml` runs `--check` before migrating; the weekly data check reports it |
| Web unit and component | Vitest + Testing Library (jsdom), `src/**/*.test.{ts,tsx}` | Formatting helpers, URL state, filters, freshness and verification display, components (missing values, demo and stale badges, card picker), dead reckoning | `pnpm test:web`, CI |
| Contract | OpenAPI schema → `src/lib/api/schema.d.ts` with `pnpm --filter web gen:api` (committed) | Frontend and API agree on shapes; `tsc` fails when the frontend uses a field the generated types lack | Regenerated by hand after an API schema change (CI doesn't regenerate it) |
| E2E | Playwright (`apps/web/e2e`) against `next build` + `next start`; API responses stubbed with `page.route`, map tiles aborted | Smoke test per route and nav, live map (live, delayed, expired, demo, unavailable), airports, lounges, checker and fares flows. Desktop Chrome and Pixel 7 projects | `pnpm --filter web test:e2e`, CI (Chromium) |
| Accessibility | axe (`@axe-core/playwright`) | Every smoke route in dark and light, and the fares results, have no serious or critical violations | CI, with the e2e run |
| Secret scan | gitleaks | No committed secrets, full history | CI |
| Performance | Lighthouse CI | Content pages and live map budgets from the PRD | Not set up yet |

## Eligibility engine: the highest-risk logic

- **Table-driven tests:** one row per rule shape (quota per period, spend gate per window, guest rules, scope, policy-version boundaries), plus named cases for "depends, never no" on missing data, arrivals and transit lounges, informational rules and the wording quoted in `detail`.
- **Property-based tests (Hypothesis)** over generated rule sets:
  - More spend never makes the answer worse; more visits used never makes it better.
  - A travel date outside a policy's `valid_from`–`valid_to` window never uses that policy.
  - A rule marked `ambiguous` never gives a plain "yes".
  - Every answer that isn't "yes" names its reason.
  - Informational rules (`entry_method`, `fee`, `add_on_cardholders`) never change the status.
- **Real seed files:** `test_seed.py` asserts that every card policy not yet `verified` carries `unmodelled_terms`, which makes the engine answer "depends" at best, so an imported, unchecked card can never produce a plain "yes".

## Data honesty tests

- Demo mode: every aircraft feature carries `is_demo=true`. The UI shows the DEMO DATA badge whenever any demo feature is present (component and e2e tests).
- Stale data: given positions older than the thresholds, the UI fades or hides them as specified.
- Missing fields render "Not available", never empty strings or zeros.

## Provider adapters

- Recorded responses served through `httpx.MockTransport` (a real Ignav response lives in `tests/fixtures/ignav`). No live calls in CI, and `conftest.py` blanks `IGNAV_API_KEY` and sets `FARE_PROVIDERS=mock` so a test can never spend the paid budget.
- Live smoke checks against adsb.lol, adsb.fi, OpenSky and adsbdb run in the **weekly data-check job** ([ADR-0013](../decisions/0013-weekly-data-check.md)) to detect upstream API changes.

## On-demand ingestion

- Single-flight lock: N concurrent requests on a stale snapshot cause exactly one upstream sweep.
- No upstream calls are made while nobody is requesting positions.
- Redis snapshot writes happen at most once every 60 s.

## Weekly data-check job

- Unit tests for the main-text extraction behind content-change detection, the state that round-trips through the issue body, link checks (changes, redirects, errors, robots), provider shape checks and rate limits, and a full run with a mocked transport that renders the report (`test_data_check.py`). Seed problems are reported in the issue, not raised.
- `pnpm data-check` runs the job locally and writes `apps/api/data-check-report.md` without opening an issue. Only the workflow opens or updates the issue.
